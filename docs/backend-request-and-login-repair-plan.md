# 网易请求保护与登录可靠性联合修复

## 目标与边界

- 面向约十五人使用，消除重复查询、请求放大、失控重试与长时间高密度访问；单人正常播放不能被固定间隔人为拖慢。
- 保持已发布版本 `c3f1cf1` 的播放业务语义：会员强制解灰，保留原有备用路径、选源方式、试听及错误音源校验。不会改成官方优先。
- 保留现有前端组件、样式、布局、字体和动效。用户触发的失败使用现有提示条及表单错误样式，说明真实的失败类别。
- 账户数据、密码、会员、头像及会话复用原存储，不进行数据库 schema 迁移或清库。
- 实施前检查并撤回上轮被叫停的七个文件中本任务自己的未提交改动；其中官方优先及未经验证的校验简化不进入本次修复。账户仓库其他未提交修改保持原样。

## 已核实的问题

1. BFF 和真实 HTTP 出口均按一秒间隔调度，第三方解析和 CDN 也受到同一排队约束。
2. 出口门禁依赖响应体的消费事件释放并发名额，UNM 的只读响应头探测可能已经成功收齐数据，却仍占用名额。本地无外网桩已复现两个成功响应阻塞第三个请求。
3. 强制解灰会进入 UNM；其歌曲详情查询确实访问网易，之后的第三方解析和 CDN 请求应分别计量，不能统统算作网易业务 API。
4. 账户服务未建立真实客户端 IP 的可信转发，所有来源成为 `unknown`，共享 IP 额度；同邮箱跨设备的失败锁定也被混在一起。
5. 登录失败锁定使用 `5206/429`，管理员权限不足也使用 `5206/403`。前端缺少上下文映射，把锁定原因隐藏成“请求失败”。

## 实施顺序

### 一、先建立回归边界

- 固定会员 `force_on` 请求链、非会员权限隔离、试听标记和音源校验用例；明确不能通过跳过检查或降低音质换取快响应。
- 增加只读头响应、正常消费响应体、连接失败、中止、重定向和并行候选的真实回环 HTTP 测试。
- 增加数字 QQ 邮箱、不同客户端 IP、相同邮箱跨 IP、相同 IP 多邮箱和错误文案的回归用例。

### 二、音乐请求保护只在实际网易业务出口执行

- 按最终请求主机和用途识别网易业务 API，包括强制解灰内部调用及重定向后的请求。第三方解析、音频/图片 CDN、本机账户通信不进入此额度。
- 网易音频 CDN 不与网易业务 API 共用频率桶。它仍遵守已有调用超时和连接释放机制，不额外添加固定等待。
- 用可容纳一次正常播放请求组的短突发预算替代逐请求固定间隔：工程初值为突发额度 3、持续补充每秒 1 次、网易业务在途上限 2。空闲后也最多积累 3 次额度；这不是网易承诺的安全阈值。
- 仅在短突发/持续预算或在途上限不足时排队；播放优先，后台查询等待，保留公平调度和队列期限。恢复时不集中补发积压任务。
- 根据真实传输完成状态释放额度，不依赖调用方必须消费响应体，也不擅自读取/丢弃调用方响应内容。
- 取消 BFF 的重复频率等待。只有确认目标 ncm-api 的实际出口保护已安装后，才进入此模式；部署和回滚同步维护配置。
- 保留公共数据缓存、相同进行中请求合并、过时操作取消和有限重试。任何需要改变依赖模块或选源语义的优化，先证明行为等价，不凭猜测删除备用步骤。
- 明确限流/风控反馈按网易作用域退避并遵守 Retry-After；普通资源不存在、第三方超时及普通 503 不升级为网易全局风控。

### 三、修复登录隔离和代理信任

- Nginx 覆盖设置真实来源头；BFF 仅从这个受控入口提取并验证 IP，向账户服务重建单一规范来源，不盲信或转发用户自行填写的 X-Forwarded-For 链。
- 音乐 BFF、账户服务生产监听限制在回环地址，账户服务只在此拓扑下启用可信代理来源。候选验证确认真实转发链，避免直接暴露可伪造来源头的账户端口。
- 未获取可信来源时不把所有用户放进同一个 `unknown` IP 桶；账户级保护继续生效。日志明确记录来源识别失败，不能静默假装已实现按 IP 隔离。
- 保持现有凭据核验、每账户保护及失败锁定门槛；修复来源隔离、失败消息和等待时间，不靠取消防暴力破解措施解决登录问题。
- 成功登录清理对应失败记录；已锁定期间的重复操作不延长锁定。不会修改用户密码或清除正常用户会话。

### 四、同风格的明确提醒

复用现有 Toast 和登录表单错误区，不增加新弹窗或改变视觉。主动提交失败只提示一次；后台续期不反复弹窗。错误码结合 HTTP 状态及 Retry-After 解释，管理员权限错误与登录锁定不能混淆。

| 场景 | 提示示例 |
| --- | --- |
| 邮箱格式不合法 | 填一个有效的邮箱。 |
| 凭据不匹配 | 邮箱或密码不对，再检查一下。 |
| 请求次数过多 | 操作有点频繁，30 秒后再试。 |
| 登录失败锁定 | 登录失败次数有点多，12 分钟后再试。 |
| 网络连接失败 | 连不上登录服务，检查一下网络。 |
| 服务暂时不可用或超时 | 登录服务这会儿没响应，稍后再试。 |
| 管理员权限不足 | 这个操作需要管理员权限。 |

- 时间来自服务端真实剩余等待时间，不写死；表单保留输入，等待期间避免重复提交，提供可见倒计时。
- 不区分“账号不存在”和“密码错误”，继续使用统一的凭据不匹配提示，避免账号枚举。
- 保留错误码、状态、traceId 供排查；不把英文堆栈、密码、Cookie、令牌或数据库内容展示/写入公开日志。

## 验收

- 单人且没有积压时，合理的短请求组立即通过，不产生一秒一跳的人工等待；与相同本地桩基线比较额外延迟。
- 第三方和 CDN 请求不会消耗网易业务额度，亦不会占住网易业务并发名额。
- 十五人模拟下，网易短突发、持续请求量及并发均受控；缓存命中和取消确实减少真实请求，限制后的恢复不出现补发尖峰。
- 会员强制解灰、选源、试听与错误音源检测结果符合基线；真实播放器功能及现有视觉保持一致。
- 一位用户失败不会占用其他 IP 的登录额度；锁定按正确账户和来源隔离；数字 QQ 邮箱正常验证；各种失败显示对应中文原因及正确倒计时。
- 直接伪造转发头不能绕过入口的来源识别，账户服务不对外监听；代理头缺失不会让全体用户共享 unknown IP 限流。
- 本机桩测试不向网易压测。运行两仓库所需单元/集成测试、桌面和手机浏览器回归、生产构建，再进行少量真实只读播放和隔离测试账号验收。

## 发布和回滚

- 仅提交本任务拥有的文件，按 `docs/release-workflow.md` 使用 `npm run deploy:echo -- --push`。
- 候选先验证出口保护及真实 IP 转发，再切换正式版本；保留原运行参数，失败恢复原进程、上游模块和配置，不覆盖数据库。
- 分别确认 `PRODUCTION_VERIFIED`、两个源码提交对应的部署回执、GitHub 推送及完整 Release 包上传，任何阶段失败都单独报告。

## 实施记录

- 网易业务出口采用 `netease-api-v2`：突发 3、每秒补充 1、在途 2；第三方/CDN 使用原生传输。回环 socket 用例确认只读响应头不会占住名额，取消请求不会继续排队发送。
- BFF 仅在出口已验证的托管部署取消重复限速。未确认来源的 429 只影响对应接口；确认的网易限流才触发整体退避。
- 登录采用受控来源转发及回环监听，保留原保护门槛。锁定、次数过多、凭据不匹配、网络和服务故障使用现有提示条和错误区域；倒计时期间阻止重复提交并保留输入。
- 本机两仓库生产构建和桌面/手机交互回归通过；两项需要独立参考服务的视觉对比用例跳过，样式和布局未修改。最终发布结果以发布脚本及双提交回执为准。
