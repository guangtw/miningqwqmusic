# 音乐上游请求保护

当前目标是单个音乐 Node 进程下约 10 人的日常使用，不能承诺网易或第三方音源不触发风控。播放音频仍由浏览器直连返回的 URL。

## 请求预算

所有发往 `MUSIC_SOURCE_BASE_URL` 的 JSON 请求及其每一次重试，经过进程内共享队列。默认并发上限 2、启动间隔 500ms、最多等待 64 个任务、单任务最多排队 25 秒；超限返回 503/code 2008，不无限堆积。网络超时从出队后开始计时。

配置项为 `MUSIC_SOURCE_MAX_CONCURRENT`、`MUSIC_SOURCE_MIN_INTERVAL_MS`、`MUSIC_SOURCE_MAX_QUEUE`、`MUSIC_SOURCE_QUEUE_TIMEOUT_MS`。这些是保守的工程起点，不是上游承诺的安全频率。上线后应根据请求延迟、失败率和实际限流记录调整。

相同 URL 的进行中请求合并；同一歌曲、音质、解灰模式和解析配置的整个播放解析也合并，包括时长查询和 HEAD 校验。详情、歌词、榜单等响应缓存 120 秒，搜索和联想缓存 15 秒。播放、解灰、下载 URL 不保存完成结果，避免复用失效链接；找不到音源的结果短暂缓存 5 秒。

权限在路由中逐次检查，游客与已授权解灰模式不会合并。缓存不包含用户会话或权限响应，Nginx 共享代理缓存继续关闭。

## 限流与故障

HTTP 429/503 或 JSON 顶层 code 429/503 立即停止当前重试，整个上游进入至少 60 秒冷却；`Retry-After` 更长时遵守其秒数或 HTTP 日期。等待中的任务立即失败，冷却后先串行探测，成功才恢复正常并发。音乐请求超时后不再立即补发，而是冷却 30 秒，避免旧解析仍在独立 ncm-api 内执行时叠加新任务。

冷却、排队拒绝、超时和网络错误向上传递，不继续切换备用音源。播放器遇到服务或网络故障停止自动跳曲，并在本地遵守冷却时间；只有明确的缺歌错误才每隔 1 秒跳过一首，单次最多尝试 3 首。音频地址续签失败不会无限扫描队列。

发布脚本仅把已知旧预设 `kuwo,kugou,migu` 迁移为当前插件支持的 `unm,msls,qijieya`。候选版本先使用新配置；正式切换前备份共享配置，回滚时恢复。其他自定义音源配置保留，不改账户数据库和 ncm-api 安装目录。

## 验证与扩容边界

回归使用本地桩，不向网易发送压力测试。覆盖 10 个同曲请求合并、不同歌曲并发/间隔、队列满和过期、限流不重试与冷却恢复、播放失败停止连跳。

共享队列通过 Node 的 `globalThis` 跨 Next 路由包复用。当前生产为单实例 fork 模式；多进程、多容器或多台主机不会共享此预算。扩容前必须把队列、冷却和必要的请求去重移至共享存储或统一上游网关。独立 ncm-api 的其他调用者也不受本站队列控制。
