# 音乐上游请求保护

当前目标是约 15 人共用一个服务器出口，优先避免连续突发请求、重复解析和失败重试叠加。以下是可测量、可调整的工程初值，不是网易公布的安全阈值。播放音频仍由浏览器直连返回的 URL。

## 请求预算

保护分两层：BFF 管理用户请求、共享缓存、优先级和取消；`ncm-api` 中的 `music-egress.cjs` 在 Node HTTP/HTTPS Agent 分配真实 socket 前准入，覆盖核心请求、解灰插件内部调用及其重试和重定向。已核对生产核心使用 Axios，UNM 使用 `node:http(s)`，均经过此出口；生产没有代理或自定义隧道 Agent。更换传输库或接入代理时必须重新验证出口覆盖，不能只根据 BFF 请求数量判断实际密度。

已验证实际出口模块 `netease-api-v2` 的部署使用单一网易业务预算：突发最多 3 次、每秒补充 1 次、最多 2 个网易业务请求在途。空闲最多积累 3 次额度，正常请求组可立即开始，持续请求超过预算才等待。最多排队 64 个任务、30 秒；所有网易重试和重定向重新准入。排队与网络超时分开计时。这些是工程初值，不是网易承诺的安全频率。

只计入 `music.163.com` 及其子域的 `/api/`、`/weapi/`、`/eapi/`、`/xeapi/` 和外链解析接口，包括 UNM 内部的歌曲详情。第三方解析、音频/图片 CDN（包括 `music.126.net`）不消耗网易额度，不增加固定等待或额外的硬超时。响应传输完成后释放名额，不要求调用方必须读取响应体。

部署确认 ncm-api 返回对应策略标识后才启用 `MUSIC_SOURCE_EGRESS_MANAGED=1`；BFF 保留请求合并、缓存、公平调度和最多 8 个 JSON 请求在途，取消重复频率等待。未安装真实出口模块时仍采用 BFF 保守回退（并发 2、间隔 1000ms），不能单独打开托管开关。

播放优先于明确的搜索/歌单操作，其次是歌词、评论和音质选项，首页及后台刷新优先级最低；同优先级轮换用户，等待 10 秒逐级提升优先级，避免一直饥饿。调度键为不可逆摘要，不记录 Cookie、令牌或用户 IP。

配置项为 `MUSIC_SOURCE_EGRESS_MANAGED`、`MUSIC_SOURCE_MAX_CONCURRENT`、`MUSIC_SOURCE_MIN_INTERVAL_MS`（仅保守回退模式）、`MUSIC_SOURCE_MAX_QUEUE`、`MUSIC_SOURCE_QUEUE_TIMEOUT_MS`。上线后根据真实网易请求、等待时间、失败率和实际限流记录调整。

相同 URL 及相同歌曲/音质/解灰模式/解析配置的整个播放解析均合并。每个等待者可以独立取消，最后一个等待者离开才取消共享工作；后台刷新例外。取消移除尚未出队的任务；已发出的 BFF 请求断开后，ncm-api 取消该调用下未完成的真实 HTTP 请求，实际传输结束前不释放网易在途名额。网易业务传输另有 15 秒硬截止。每个 BFF 播放流程总共最多 5 次 JSON 尝试，其他流程最多 8 次；每次 ncm-api 调用内部最多 8 次网易业务准入。单个 JSON 请求最多重试一次，超时和限流不立即重试。

基础信息、音质原始元数据和歌词缓存 6 小时；解析后的音质选项缓存 1 小时；歌单 2 分钟；首页/榜单等 10 分钟；搜索/联想 45 秒；评论 20 秒。公共元数据允许有界过期内容先返回，同时合并一次低优先级更新，刷新失败至少间隔 10 秒再试；评论不使用过期数据。播放、解灰及下载 URL 不保存完成结果，找不到音源的结果只缓存 5 秒。

播放请求原样传递所选音质，不根据音质菜单缓存预先改档；打开菜单不影响播放选源。每次播放最多查询一次共享缓存的歌曲详情，用于比较音源时长，已有详情缓存时不会重复请求上游。播放器同一轮切歌合并，切歌/清队列取消旧播放和歌词请求；搜索切换取消过时的查询和综合搜索的后续艺人查询。百科仅在实际打开内页或菜单时查询，评论在进入评论区时查询。

权限在路由中逐次检查，游客与已授权解灰模式不会合并。缓存不包含用户会话或权限响应，Nginx 共享代理缓存继续关闭。

## 限流与故障

明确的 429 或 JSON code 429 停止当前重试，并遵守秒数或 HTTP 日期形式的 `Retry-After`（最少一个请求间隔），不把短等待强制放大为 60 秒。网易出口确认限流时按 30/60/120/240/300 秒退避；稳定十分钟后允许重置阶梯，单次成功不会立即重置。已确认的网易限流通过响应头传播到 BFF；混合第三方解析的未确认 429 只暂停对应 BFF 接口，不推断整个网易出口遭到风控。

普通 503 不等同于全局限流；指定了 `Retry-After` 时只暂停当前接口。单次超时不会暂停全站；同一接口 30 秒内三次失败后暂停该接口 5 秒，其他接口和缓存仍可使用。恢复时只放行一个真实待处理请求，恢复探测按加长间隔启动，成功后再恢复正常并发。进程重启保留出口最近一次启动时间和未到期的冷却记录，状态文件只保存在服务器共享目录，绝不进入发布包。

未设置高音质优先偏好时，默认先请求官方音源（`unblock=false`）。官方完整可播时直接采用，即使实际音质低于所选档位，也不额外查询解灰。只有试听、时长不足、缺失 URL 或已有音源校验失败，才为有权限的用户调用现有解灰匹配路径；游客不解灰。确认完整官方音源正以极高播放后，用户主动选择更高档位，会持久保存 `preferUnblock=true`，后续切歌和刷新使用 `force_on`。展示层可调用 `switchToStableSource()` 让当前这首临时使用 `force_off`；下一首恢复持久偏好。接入约定见 [音源偏好与前端交接](playback-source-preference-handoff.md)。

优先用音源返回的毫秒时长与同 ID 歌曲详情比较，允许 2–5 秒的尾部/舍入误差，避免把完整的短歌误判成试听；详情不可用时保留原试听时长启发式。已有 HEAD 类型/体积校验继续生效。这些校验用于发现不完整或异常地址，不是解码后的精确时长或同一录音身份校验。备用匹配最多按顺序尝试两个已配置 source；整个流程仍受总尝试预算约束。UNM 自身的候选并行和 CDN 校验保持原生行为。局部音源失败允许尝试后续音源，明确全局限流或总预算用尽则停止。

播放响应分开返回 `requestedLevel` 与音源报告的 `level`。兼容响应中的音质字段统一提取，明确返回的档位优先采用；官方没有档位但有明确有损格式和码率时，只推导标准/较高/极高。按用户确定的展示规则，解灰只返回链接、没有档位时，沿用上游 v1 的回填约定，将本次请求档位回填为 `level`，不新增音频下载或检测。这属于接口报告约定，不是独立文件鉴定。播放器收到结果就更新常驻音质标记并提示明确的回退，无需打开菜单；用户的音质偏好保留。

解灰请求环绕声/杜比档位（`jyeffect`、`sky`、`dolby`）时，先使用共享的网易曲库音质元数据确定可用回退，再把有效档位传给上游。比如没有杜比但有沉浸环绕声时，请求 `sky`，响应保留 `requestedLevel=dolby`、返回 `level=sky`。底栏、正在播放标记和所选卡片说明共用播放结果；打开菜单不触发重新选源。此规则不改变母带、Hi-Res、无损及普通档位的既定请求约定。歌曲详情复用既有缓存，冷缓存空间音质解析最多增加一次 `/song/music/detail` 查询，保持原限流与总尝试预算；元数据缺失时保留原请求档位，明确全局限流、取消和预算用尽则立即停止。

播放器只有明确限流时才设置全局禁止重试时间，提示实际剩余秒数；不再使用“音乐服务正在恢复”。单曲超时或普通网络失败不阻止用户立即尝试其他歌曲；服务故障不会自动扫描队列。只有明确缺歌错误才每隔 1 秒跳过一首，单次最多 3 首。

发布脚本仅把已知旧预设 `kuwo,kugou,migu` 迁移为当前插件支持的 `unm,msls,qijieya`。候选版本先使用新配置；正式切换前备份共享配置，回滚时恢复。其他自定义音源配置保留，不改账户数据库和 ncm-api 安装目录。

## 验证与扩容边界

回归使用本地桩，不向网易发送压力测试。覆盖正常短突发、十五个独立请求的持续密度与并发、相同请求合并、有界过期缓存和刷新失败退避、公平调度、共享取消、作用域故障、单次恢复探测及总尝试预算。隔离 Node 子进程用假 DNS 指向回环服务，验证真实 socket、排队取消、只读响应头完成释放，以及网易冷却期间第三方和 CDN 仍可通行；同一验证在 Linux 候选部署时执行。

每分钟分别输出 `music_requests`（BFF）和 `music_egress`（仅网易业务）聚合指标：命中/合并、排队/在途、开始/成功/失败/取消、限流次数、排队累计耗时等。允许短突发后，最小启动间隔可以是零，不能据此认定持续密度失控；应检查突发额度和持续补充的时间窗口。只通过受保护的服务器日志查看，不开放公开诊断接口。

共享队列和请求上下文通过 `globalThis` 跨 Next 路由包复用。当前 BFF 和 ncm-api 均为单实例 fork 模式；ncm-api 的其他调用者也经过真实出口限速。多进程、多容器或多机扩容前必须把出口预算、冷却和必要的请求去重移至统一网关或共享存储，不能让每个实例各自拥有一份额度。

发布脚本从本次源码包加载出口预加载模块，保存原 `NODE_OPTIONS` 和相关进程设置。Linux socket 验证通过后启用；候选或正式验收失败时恢复原上游设置。账户库、会话、头像和 ncm-api 安装源码均不更改。
