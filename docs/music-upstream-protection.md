# 音乐上游请求保护

当前目标是约 15 人共用一个服务器出口，优先避免连续突发请求、重复解析和失败重试叠加。以下是可测量、可调整的工程初值，不是网易公布的安全阈值。播放音频仍由浏览器直连返回的 URL。

## 请求预算

保护分两层：BFF 管理用户请求、共享缓存、优先级和取消；`ncm-api` 中的 `music-egress.cjs` 在 Node HTTP/HTTPS Agent 分配真实 socket 前准入，覆盖核心请求、解灰插件内部调用及其重试和重定向。已核对生产核心使用 Axios，UNM 使用 `node:http(s)`，均经过此出口；生产没有代理或自定义隧道 Agent。更换传输库或接入代理时必须重新验证出口覆盖，不能只根据 BFF 请求数量判断实际密度。

两层默认均最多 2 个在途请求、启动间隔 1000ms、不累积空闲额度、最多排队 64 个任务、最多排队 30 秒。所有重试都重新准入，恢复后不会集中补发。BFF 配置最低间隔钳制为 1000ms、并发最多为 2；出口也保持相同下限。排队与网络超时分开计时。

播放优先于明确的搜索/歌单操作，其次是歌词、评论和音质选项，首页及后台刷新优先级最低；同优先级轮换用户，等待 10 秒逐级提升优先级，避免一直饥饿。调度键为不可逆摘要，不记录 Cookie、令牌或用户 IP。

配置项为 `MUSIC_SOURCE_MAX_CONCURRENT`、`MUSIC_SOURCE_MIN_INTERVAL_MS`、`MUSIC_SOURCE_MAX_QUEUE`、`MUSIC_SOURCE_QUEUE_TIMEOUT_MS`。这些是保守的工程起点，不是上游承诺的安全频率。上线后应根据请求延迟、失败率和实际限流记录调整。

相同 URL 及相同歌曲/音质/解灰模式/解析配置的整个播放解析均合并。每个等待者可以独立取消，最后一个等待者离开才取消共享工作；后台刷新例外。取消移除尚未出队的任务；已发出的 BFF 请求断开后，ncm-api 取消该调用下未完成的真实 HTTP 请求，真实 socket 结束前不释放在途名额。真实网络请求另有 15 秒硬截止。每个 BFF 播放流程总共最多 5 次 JSON 尝试，其他流程最多 8 次；每次 ncm-api 调用内部也最多 8 次 HTTP 准入。单个 JSON 请求最多重试一次，超时和限流不立即重试。

基础信息、音质原始元数据和歌词缓存 6 小时；解析后的音质选项缓存 1 小时；歌单 2 分钟；首页/榜单等 10 分钟；搜索/联想 45 秒；评论 20 秒。公共元数据允许有界过期内容先返回，同时合并一次低优先级更新，刷新失败至少间隔 10 秒再试；评论不使用过期数据。播放、解灰及下载 URL 不保存完成结果，找不到音源的结果只缓存 5 秒。

播放前只使用已缓存的音质信息进行降级，不再强制发出两次元数据查询。播放器同一轮切歌合并，切歌/清队列取消旧播放和歌词请求；搜索切换取消过时的查询和综合搜索的后续艺人查询。百科仅在实际打开内页或菜单时查询，评论在进入评论区时查询。

权限在路由中逐次检查，游客与已授权解灰模式不会合并。缓存不包含用户会话或权限响应，Nginx 共享代理缓存继续关闭。

## 限流与故障

明确的 429 或 JSON code 429 停止当前重试，并遵守秒数或 HTTP 日期形式的 `Retry-After`（最少一个请求间隔），不再把短等待强制放大为 60 秒。缺少等待时间时按 30/60/120/240/300 秒退避；稳定十分钟后允许重置阶梯，单次成功不会立即重置。ncm-api 出口按实际目标分组：网易域名共享一组，其他音源按目标主机摘要隔离。已确认的网易限流通过响应头传播到 BFF。

普通 503 不等同于全局限流；指定了 `Retry-After` 时只暂停当前接口。单次超时不会暂停全站；同一接口 30 秒内三次失败后暂停该接口 5 秒，其他接口和缓存仍可使用。恢复时只放行一个真实待处理请求，恢复探测按加长间隔启动，成功后再恢复正常并发。进程重启保留出口最近一次启动时间和未到期的冷却记录，状态文件只保存在服务器共享目录，绝不进入发布包。

解灰主请求明确指定首选 source，备用匹配最多按顺序尝试两个已配置 source，避免调用插件的隐式遍历所有音源路径；整个流程仍受总尝试预算约束。局部音源失败允许尝试后续音源，明确全局限流或总预算用尽则停止。

播放器只有明确限流时才设置全局禁止重试时间，提示实际剩余秒数；不再使用“音乐服务正在恢复”。单曲超时或普通网络失败不阻止用户立即尝试其他歌曲；服务故障不会自动扫描队列。只有明确缺歌错误才每隔 1 秒跳过一首，单次最多 3 首。

发布脚本仅把已知旧预设 `kuwo,kugou,migu` 迁移为当前插件支持的 `unm,msls,qijieya`。候选版本先使用新配置；正式切换前备份共享配置，回滚时恢复。其他自定义音源配置保留，不改账户数据库和 ncm-api 安装目录。

## 验证与扩容边界

回归使用本地桩，不向网易发送压力测试。覆盖十五个独立用户请求的间隔与并发、十五个相同请求合并、有界过期缓存和刷新失败退避、公平调度、共享取消、作用域故障、单次恢复探测、总尝试预算。另在隔离 Node 子进程用假 DNS 指向回环 HTTP 服务验证十五个真实 socket 请求及排队取消；同一验证会在 Linux 候选部署时执行。

每分钟分别输出 `music_requests` 和 `music_egress` 聚合指标：命中/合并、排队/在途、开始/成功/失败/取消、限流次数、排队累计耗时、实际启动最小间隔等。只通过受保护的服务器日志查看，不开放公开诊断接口。评估限速参数时结合增量指标、请求延迟和失败率；十五首不同歌曲同时冷启动必然有排队时间，不通过增加突发并发隐藏这一取舍。

共享队列和请求上下文通过 `globalThis` 跨 Next 路由包复用。当前 BFF 和 ncm-api 均为单实例 fork 模式；ncm-api 的其他调用者也经过真实出口限速。多进程、多容器或多机扩容前必须把出口预算、冷却和必要的请求去重移至统一网关或共享存储，不能让每个实例各自拥有一份额度。

发布脚本从本次源码包加载出口预加载模块，保存原 `NODE_OPTIONS` 和相关进程设置。Linux socket 验证通过后启用；候选或正式验收失败时恢复原上游设置。账户库、会话、头像和 ncm-api 安装源码均不更改。
