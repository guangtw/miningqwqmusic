# 一起听同步约定

本次同步 GitHub 前端 `a42c395`，保留其样式、布局和交互动效，仅修改一起听与播放器内部逻辑。

- 所有人都能操作播放。最近一次执行播放、暂停、换歌、拖进度或改队列的人负责后续进度上报及自动切歌，其余成员跟随房间，避免多台设备各自随机切歌或抢写进度。
- 服务端以自己的时间记录状态，并提供时钟同步信息；进度报告携带基础版本，过期报告或非当前控制者的报告不能覆盖新的暂停、定位、播放模式和队列。
- 顺序播放和列表循环分别同步，单曲循环和随机播放保留。清空房间队列会停止所有成员的播放。
- 客户端串行提交控制请求，按递增版本接收事件，旧 HTTP 响应、重放事件和已离开会话的请求不会覆盖新状态。同账号另一设备的操作也会跟随。
- 切换歌曲取地址时保留最新定位和播放意图，避免重复取地址或暂停后又被旧请求自动播放。网络暂时失败保留已保存房间，恢复网络或回到页面后重同步；SSE 长时间无数据时重连。
- 加入新房间失败保留原房间，成功后再退出原房间。房主离开会转交给剩余成员；没有心跳也没有活动流的成员在宽限期后移除。取消订阅会释放服务器流和计时器。

发布流程在候选服务和正式 HTTPS 上都使用两个隔离账号，验证加入、SSE 实时定位、暂停不被旧进度覆盖、房主转移、清空队列及退出关闭流。仅按测试生成的 ID 与邮箱精确清理账号和关联数据。

房间仍采用现有的进程内存模型，最长保留六小时；账户数据库和 Cookie 不改变。账户服务进程重启后需要重新创建房间。浏览器自动播放限制、各账号可播放的音源/试听权限仍然适用。
