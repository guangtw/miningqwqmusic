# 音乐上游请求保护

当前目标是单个音乐 Node 进程下约 10 人的日常使用，不能承诺网易或第三方音源不触发风控。播放音频仍由浏览器直连返回的 URL。

## 请求预算

所有发往 `MUSIC_SOURCE_BASE_URL` 的 JSON 请求及其每一次重试，经过进程内共享队列。默认并发上限 4，其中最多 2 个名额供非播放请求使用，播放请求优先出队。令牌桶允许空闲后立即启动 4 个请求，随后每 500ms 补充一个名额，避免给单人正常操作逐个添加固定延迟。最多等待 64 个任务、单任务最多排队 15 秒；超限返回 503/code 2008，不无限堆积。网络超时从出队后开始计时。

配置项为 `MUSIC_SOURCE_MAX_CONCURRENT`、`MUSIC_SOURCE_MIN_INTERVAL_MS`（令牌补充间隔）、`MUSIC_SOURCE_BURST`、`MUSIC_SOURCE_MAX_QUEUE`、`MUSIC_SOURCE_QUEUE_TIMEOUT_MS`。这些是工程起点，不是上游承诺的安全频率。上线后应根据请求延迟、失败率和实际限流记录调整。

相同 URL 的进行中请求合并；同一歌曲、音质、解灰模式和解析配置的整个播放解析也合并，包括时长查询和 HEAD 校验。详情、歌词、榜单等响应缓存 120 秒，搜索和联想缓存 15 秒。播放、解灰、下载 URL 不保存完成结果，避免复用失效链接；找不到音源的结果短暂缓存 5 秒。

播放路由将用户所选九档 `level` 原样交给适配器，不根据原生目录缓存预先改成另一档，避免 Dolby 变成 sky、母带变成 Hi-Res。打开音质菜单仍会查询并缓存完整音质选项；目录信息不代表解灰来源的实际能力。原曲时长与 HEAD 校验并行、分别限制到 1.5 秒，缺失的辅助信息不阻断已有的原生可用地址。

会员默认使用 `force_on`：先按配置逐个请求 `/song/url/match?source=...&level=...`，所有解灰候选不可用或身份校验不通过时才回退 `/song/url/v1?unblock=false`。显式 `auto` 保留原曲优先，游客或显式 `force_off` 只走原生地址。精确匹配所选档位的候选优先，不再因文件规格更高就提前停止查找；无精确档位时返回实际可用档位，前端保留选择偏好并显示实际音质。不会把原生 `unblock=true` 分支回填的请求档位当作新的能力证明。

解灰接口在对象、数组或 URL 旁明确返回的有效 `level` 原样保留，不能用音频位深、采样率推断出的 `hires` 覆盖 `jyeffect`、`sky`、`dolby`、`jymaster`。音频检查继续用于身份和完整时长；仅当旧来源没有音质字段、只给 URL 时才推断普通编码档位，不擅自补出音效或母带。

当前服务器安装的 `/song/url/match` 实现只将 `id` 和 `source` 传给底层，忽略 `level`，响应仅为 URL；`/song/url/v1?unblock=true` 同样调用这个匹配器，并把请求的 `level` 回填进响应。保留本站九档原样请求并不意味着该旧实现能提供九种不同文件。现有免登录解灰保留，未登录网易 VIP 的状态已通过 `/login/status` 和 `/vip/info` 只读核对；用户选择暂不接入网易会员 Cookie。

文档另有 `/song/download/url/v1`，支持九档参数，注明免费歌可取更高音质。当前服务器无网易登录态，2026-11-01 对《小胡同》的逐档低频测试返回空地址/权限错误，故未将它假定为可用来源、未额外接入新的登录流程。`/song/music/detail` 提供歌曲各档文件信息，但列出某档不等于当前调用者可获取该档。

2026-11-01 启用现有解灰库的无损配置后，《小胡同》和《予你》均取得完整的 24-bit / 48 kHz FLAC，《Always Online》取得完整普通无损。此为对应文件的实测结果，不能据此证明网易母带或专属音效。
备用地址不相信接口回显的歌曲 ID、`time` 或文件大小：用 Range 最多读取 512 KiB 音频头，最多等待 3 秒，读取真实时长和标签；即使 CDN 忽略 Range，也在字节上限取消下载。真实时长必须与原曲相差不超过 3 秒。有歌名、歌手标签时必须吻合，保留伴奏、翻唱、现场等版本后缀。跨平台地址必须同时具备吻合的歌名、完整歌手列表和时长；ID 回源的网易 `music.126.net` 文件允许缺少标签，但仍检查真实时长，已有标签冲突时照样拒绝。该例外依赖原始 CDN 和 ID 回源，时长本身不构成录音身份的完全证明。拒绝一个候选后继续下一个，均不可用才保留原曲试听或报告不可用，不关闭 VIP 解灰。

权限在路由中逐次检查，游客与已授权解灰模式不会合并。缓存不包含用户会话或权限响应，Nginx 共享代理缓存继续关闭。

## 限流与故障

HTTP/JSON 429，以及有 `Retry-After` 或明确高频提示的 503，立即停止当前重试。网易原生请求与各个第三方音源分别维护冷却，至少 60 秒；`Retry-After` 更长时遵守其秒数或 HTTP 日期。只拒绝对应来源的等待任务，其他来源继续服务；冷却后先串行探测，成功才恢复正常并发。

普通 503、单次超时和网络故障不等同于 IP 风控，不触发全站冷却。超时不立即重试；第三方音源超时后只暂避该音源 30 秒，以减少 ncm-api 内残留解析叠加的机会，同时尝试原生地址或其他配置音源。解灰不重试相同失败请求，不再优先无参数遍历整个插件目录。播放、搜索、歌词等操作使用各自的熔断器，单曲超时与已处理的冷却/排队错误不累计成整项功能熔断。失败日志只记录接口路径、来源和错误码，不记录播放地址、Cookie 或令牌。

播放器遇到服务或网络故障停止自动跳曲，但允许用户立即手动重试或换歌；只有明确的限流响应才设置本地冷却。只有明确的缺歌错误才每隔 1 秒跳过一首，单次最多尝试 3 首。音频地址续签失败不会无限扫描队列。

发布脚本把已知旧预设 `kuwo,kugou,migu` 迁移为当前插件支持的 `unm,msls,qijieya`。候选版本先使用新配置；正式切换前备份共享配置，回滚时恢复。上游 `ncm-api` 通过 PM2 环境启用 `ENABLE_FLAC=true` 和 `FOLLOW_SOURCE_ORDER=true`，让现有解灰库优先按 ID 获取无损，再考虑搜索来源；不并发扫所有来源。完整原进程配置只保存在受保护的发布备份中，候选或正式验收失败时恢复旧开关并保存 PM2 状态。其他自定义音源配置保留，不改账户数据库和 ncm-api 安装目录。候选与正式站均用临时会员验证两首免费歌能返回完整无损或 Hi-Res。

## 验证与扩容边界

回归使用本地桩，不向网易发送压力测试。覆盖 10 个同曲请求合并、突发与持续流量预算、队列满和过期、真实限流不重试、来源隔离、后台请求不占满播放名额、慢音源回退、播放失败停止连跳及允许手动换歌，以及原曲优先、VIP 试听继续解灰、同名错歌手/伴奏/现场版/错误时长拒绝、音频头解析和下载上限。2026-11-01 另做五首歌的低频顺序实测：《小胡同》（郑润泽）、《予你》（队长）走原曲；《Always Online》《江南》《愿与愁》（林俊杰）从试听解灰到真实约 225、268、232 秒音频。此为该次实测结果，不保证第三方音源永久可用，不做真实上游并发压测。

共享队列通过 Node 的 `globalThis` 跨 Next 路由包复用。当前生产为单实例 fork 模式；多进程、多容器或多台主机不会共享此预算。扩容前必须把队列、冷却和必要的请求去重移至共享存储或统一上游网关。独立 ncm-api 的其他调用者也不受本站队列控制。
