# 一人一码会员协议

永久邀请码：`Mining-VIP-2-<32位十六进制随机标识>`。编号由数据库序列预留，不回收、不依赖兑换先后。当前旧会员保留为第 1 位，两张待发永久码预留第 2、3 位。随机部分使用 `crypto.randomBytes(16)`（128 bit），数据库仅保存带服务端秘密的 SHA-256 摘要。

限时邀请码：`Mining-VIP-3d-<随机标识>`、`Mining-VIP-30d-<随机标识>`。天数从首次成功兑换时按 24 小时计时；有效限时会员用新的限时码续期时，从原到期时间追加天数。限时码发行时不预占编号，首次开通时分配；续期保留编号。升级为永久时使用永久码预留的编号。永久会员不会消耗其他未使用码。

每个邀请码永久绑定首次兑换的账号 ID；账号删除也不释放。兑换、占用和授权在同一个 SQLite 写事务内完成。同账号重试只读取现有授权，不能续时、恢复撤销或转让；其他账号返回 `409 / 5502`。旧共享码全部停用，已开通会员不受影响。注册仍开放且邀请码可选。

## 前端接口字段

登录、续期、`GET /api/account/auth/me` 的 `playbackAuthorization`，以及 `GET /api/account/music/unblock/entitlement`、`POST /api/account/music/unblock/redeem`、管理员授权列表/开通/撤销接口，都返回以下会员字段：

| 字段 | 含义 |
| --- | --- |
| `enabled` | 当前是否有效；到期或撤销立即为 false |
| `membershipKind` | `permanent` / `timed`；未开通时省略 |
| `memberNumber` | 会员编号；到期/撤销后仍保留 |
| `expiresAt` | 限时会员到期 ISO 时间；永久会员为 null |
| `status` | `active` / `expired` / `revoked`；未开通时省略 |
| `grantedAt` | 本次开通/续期时间 |
| `version` | 授权变更版本；判断权限必须同时检查 enabled |

兑换接口兼容保留 `redeemedAt`、`inviteLabel`。前端存储已透传新字段，本次没有修改会员卡视觉，后续可直接按字段显示“永久会员 · 第 2 位”或到期日期。到期使用服务端时间判断，播放权限检查从数据库读取，不依赖前端显示。管理员手动开通仍为永久会员；管理员角色与会员授权相互独立。

## 发码

在账户服务目录执行 `node scripts/create-unblock-invite-code.mjs --count 2 --label 永久会员 --output /root/private-batch.json`。限时码加 `--days 3` 或 `--days 30`。`--expires-at` 仅限制可兑换的截止时间，不是会员的到期时间。禁止手工指定/重置已有邀请码，重跑发行会产生新码，不能当作查看旧码使用。

明文仅写入指定的私有输出文件（600，拒绝覆盖），标准输出不打印码。输出必须放在仓库和 public 目录之外；不得提交 GitHub、打包进 Release 或出现在公开日志里。

## 专用迁移与回滚

迁移目录 `20261101130000_single_use_memberships` 添加字段、唯一索引与编号序列；按旧授权时间/ID 给现有会员编号，保留全部用户、会话、授权、头像及原库路径。旧共享码停用。脚本事务内核对用户/会话/授权数量不变，失败整笔回滚。

发布脚本只接受 plan.json 中旧 schema、新 schema、迁移 SQL 三个确切 SHA-256；其余 schema 变化仍拒绝。两服务构建通过后，先用 SQLite 在线 backup 备份到 root 私有发布目录，再执行专用迁移，然后跑候选和正式验收。新码在正式验收通过后才发行和交付。

首次切换失败可回退旧程序并保留新增字段；旧会员继续有效，旧共享码仍停用。禁止恢复整个旧库覆盖上线后新写入的数据。正式开始发码后，旧程序不认识一次性/到期规则，**后续回滚必须选支持本协议的版本**；若确需回到迁移前代码，应先暂停兑换与播放授权并单独制定兼容补丁。当前方案不删除字段、不删除会话、不发布空库。
